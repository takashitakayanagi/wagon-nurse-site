## 3. いちばん重要な設計判断：CVをLINEではなくフォームにした

WAGONのtoC動線は原則 **CV = LINE相談**（そこから人力オペレーションでサブスクへ）。
理由は、月20,000円を冷たいトラフィックに直販するとCVが週2〜3件にしかならず、
Meta/Googleの自動入札が学習できないため（目安は広告セットあたり週50CV）。

**模試LPはこの原則の例外。** ユーザーの言葉で
「LINEで申込みがきても結局フォームに飛ばす」から。
LINEを挟むと1ステップ増えるだけで何も足していないので、申込はフォームで完結させた。

LINEは消していない。**フォームでは代わりにならない用事**に回してある
（同じ用事で2つのボタンを並べない）。

| 場所 | ラベル | 行き先 |
|---|---|---|
| 漫画直後 / WAGON紹介 / 学年分岐 / 最終CTA / 追従 | 無料で模試に申し込む | フォーム |
| 悩みセクション（2つめのCTA） | 無料解説講義についてLINEで聞く | LINE |
| 主CTAのすぐ下（小さいテキストリンク） | どの模試を受けるか迷ったらLINEで相談 | LINE |
| 解説講義セクション | 無料解説講義をLINEで聞いてみる | LINE |
| LINEセクション | LINEで相談してみる | LINE |

テキストリンクも消してフォーム一本にするなら `site.flags.showLineSubLink = false`。

### この判断で開いた穴（回す前に塞ぐこと）

1. **「送信した」が測れない。** Googleフォームは外部サイトなので追えるのはクリックまで。
   `generate_lead` はクリック数で、実際の申込より多く出る。
   → **フォーム側の回答数と突き合わせて読む。**
2. **LINEの友だちが増えない。** 収益は成績が返ったあとの解説講義とサブスクなので、
   フォームで完結すると次に連絡する経路が無い。
   → **Googleフォームの確認メッセージにLINE友だち追加URLを入れる**（フォーム側の設定）。

## 4. 計測

`lp_variant = "moshi"`。IDは本体と共通
（GA4 `G-FXKCWMXKJB` / Meta Pixel `2817935241910493` / Clarity `ybfkyv1j57`）。

| 操作 | GA4 | Meta | パラメータ |
|---|---|---|---|
| フォームのクリック | `cta_click` + `generate_lead` | 標準 `Lead` | `cta_goal="form"` |
| LINEのクリック | `cta_click` + `contact` | **Leadは立てない** | `cta_goal="line"` |
| 学年ボタン | `exam_year_select` | — | `exam_year="final"\|"junior"` |
| スクロール | `scroll_depth` | — | `percent_scrolled` 25/50/75/90 |

LINEで `Lead` を立てないのは、広告の最適化信号にフォーム以外を混ぜないため。
両方 `cta_click` は送るので `cta_goal` で切り分けられる。

`scripts/weekly-report.js` は `pagePath CONTAINS '/lp/'` と
`cta_click`/`generate_lead`/`begin_checkout` で拾うので、このLPも集計に乗る。
（以前「イベント名が違うのでレポートに出ない」と記録していたが誤り。）

**数値を読む3つの規則**（過去に誤読した）:
1. イベント件数ではなく実人数（totalUsers）で見る。件数は2倍以上に膨らむ。
2. 配信前日以前のイベントは全て自社テストとして除外する。
3. LINE側は「前日比」を平常値と比較する。gross と net を混同しない。

## 6. 学年の出し分け

「あなたはどちらですか？」で分岐。押すと sessionStorage に保存され、以降の全イベントに付く。

| | 最終学年・既卒 | 1〜3年生 |
|---|---|---|
| カウントダウン | **表示する**（第116回まで残りN日 + 2027年2月14日（日）） | **表示しない** |
| 対象模試 | 必修対策模試 / 夏模試 / 冬模試 | 基礎学力確認模試 |
| 見出し | 今の位置を知って、残りの時間の使い方を決める | 国試対策を始める前に、今の基礎学力を知る |

**低学年に月20,000円と国試カウントダウンを見せない**のは全LP共通のルール。

## 7. どこを直せばどこが変わるか

**LP上のテキスト・画像・表示フラグはすべて `src/config/site.ts`。**
コンポーネント側に文言はハードコードしていない。

| 直したいもの | 場所 |
|---|---|
| 漫画のコマ数・alt | `mangaSlides`（**配列の要素数＝表示枚数**） |
| 漫画直後の語りかけ | `afterManga`（`｜` は「ここで改行してよい」の印） |
| 学年ごとの案内・対象模試 | `gradeBranch` |
| 国試日 | `examDate` |
| 無料解説講義の日程（4枚のカード） | `freeKaisetsu.items` |
| 上部に出す無料解説講義の一文 | `freeKaisetsu.lead` |
| 解説講義の価格（現在は非表示） | `kaisetsu.items` |
| CTAの文言 | `cta`（2つめだけ `problemLabel`。行き先もLINE） |
| 受講生の声 | `voices`（カードは `excerpt`＝原文から連続した一節。原文は `full` に保持） |
| FAQ | `faqs` |
| ページタイトル・OGP・h1 | `seo`（`h1` は sr-only。漫画より上に見出しを出さない方針のため非表示） |
| 各種オンオフ | `site.flags` |
| 配色 | `tailwind.config.ts` |

**配色は漫画LPと別**。漫画LPはWAGONピンク（`#F45D9B`）＋クリーム地、
模試LPはネイビー（`#274B7A`）＋寒色の淡い地（`#F5F7FA`）。
アクセントは淡い金（`#FDF6E3` / `#D4A62A`）で、ネイビーだけで沈まないように
転換部分（希望・注記・アイコン地）にだけ温度を足している。
**申込フォームのボタンだけがピンク**（`cta.500 = #D6357A`）。ページ内で唯一の暖色の面なので、
このピンクを他（学年ボタン・見出し・アイコン）に広げないこと。広げるとCTAが埋もれる。
LINEボタンは緑（`#06C755`）のままなので、ピンク＝申込 / 緑＝相談 で色でも用事が分かれている。
漫画の絵を作り直すときは、絵の地・強調はネイビー寄りにし、
作中のボタンだけピンクにするとLP側と揃う（現行6枚は全体がピンク基調で浮いている）。
色を変えるときは `tailwind.config.ts` に加えて `src/app/globals.css` の body 2行と
`src/app/layout.tsx` の `themeColor` も一緒に直すこと（この3か所だけ実値を持っている）。

独自コンポーネント（manga LPには無いもの）:

- `ApplyButton.tsx` … 主CTA（フォーム）。`trackApply` を呼ぶ
- `LineTextLink.tsx` … 主CTA下の小さいLINEリンク。`trackLine` を呼ぶ
- `GradeBranchSection.tsx` … 学年出し分け＋カウントダウン
- `KaisetsuSection.tsx` … 解説講義の価格カード

## 9. ローカルでの確認手順（ここで何度もハマった）

1. **`node` / `npm` がPATHに無い。** PowerShellで
   `$env:Path = "C:\Program Files\nodejs;" + $env:Path` を先に実行する
   （Bashツールからは node が見えない）。
   なお同じスクリプト内で `Remove-Item` を使うと、`"C:\Program Files\..."` の
   ダブルクォート内展開がサンドボックスの保護パス判定に引っかかって止まることがある。
   上のように文字列連結で書けば通る。
2. **`npm run dev` のCSSは当てにならない。** dev serverだと
   `.phrase > span` の `display:inline-block` や `.section-heading` の
   `text-wrap:balance` が効かず、文節途中で改行しているように見える。
3. だから確認は必ず **本番ビルド** で:

```bash
cd lp-src/moshi && npm run build
```

   `NEXT_PUBLIC_BASE_PATH=/lp/moshi` を付けてビルドし、`out/` を `site/lp/moshi/` にコピー、
   `serve.ps1`（port 5500）で `http://localhost:5500/lp/moshi/` を開く。
   `site/lp/moshi/` は `.gitignore` 済み。
   （`index.txt` のコピーが権限エラーになることがあるが、RSCペイロードなので無視してよい）

### 確認済みの項目（回帰したら疑うところ）

- 実機幅375px：禁則違反なし／横スクロールなし／文節途中の改行なし
- プレースホルダー6枚とも表示、壊れた画像アイコンが出ない
- `basePath` が画像に効いている（`/lp/moshi/images/...`）
- 低学年側にカウントダウンも金額も出ない
- イベント発火（フォーム→`generate_lead`+`Lead`、LINE→`contact`のみ）

manga LPへのbackportは別タスクとして登録済み。

## 12. コピーを書くときの約束

ユーザーから繰り返し指摘されている基準。破ると差し戻される。

- **言わなくても伝わることを、形式のために足さない。** 出典・根拠ブロックは
  2回続けて却下された。「〜という理由で」を説明したくなったら、まず消せないか考える
- **オファーをCTAの前に使い切らない**
- **借りた形式は規則に従う**（SOAP形式のLPで、O欄に観察事実以外を書いて指摘された）
- **WAGON側の発話はすべて敬語。ら抜き言葉を使わない**
- **診断結果を意図的に歪めない。** 「循環器が必ず要対策になるよう問題設計を」という
  案は、データに基づくというWAGONの主張を損ない、担任の初手を潰し、
  友人同士で見比べたときに露見するため採らなかった
- 数字を出すときは出所を確認する。無ければ書かない
